# TCP-сервер и клиент

Сервер хранит один атомарный счётчик `uint64`, начальное значение — 0. Каждый корректный запрос увеличивает его на 1. Счётчик общий для всех подключений.

Запуск сервера:

```sh
go run ./cmd/server -listen :9000
```

По умолчанию сервер создаёт столько воркеров, сколько `GOMAXPROCS`. Их число можно задать через `-workers`, например `go run ./cmd/server -listen :9000 -workers 12`.

Запуск клиента в другом терминале:

```sh
go run ./cmd/client 127.0.0.1 9000
```

Для суммарной нагрузки через несколько сокетов: `go run ./cmd/client -connections 4 127.0.0.1 9000`.

Для наибольшей суммарной скорости на многопроцессорной машине можно запустить несколько отдельных процессов клиента: тогда их атомарные счётчики ID не конкурируют друг с другом. ID уникален внутри каждого процесса клиента.

Клиент хранит атомарный `uint64` ID и увеличивает его перед каждым запросом. Он отправляет запросы пачками, не ожидая ответа перед следующим запросом. Ответы читает одновременно с отправкой и раз в секунду показывает скорость отправки (`sent/s`) и получения ответов (`responses/s`). Когда буфер TCP заполнен, запись в сокет блокируется до появления места. При обрыве соединения клиент повторяет подключение. Остановка — Ctrl+C.

Сервер и клиент читают через буфер 64 КБ. Сервер передаёт разобранные запросы пачками в пул воркеров и повторно использует память пачек через `sync.Pool`. Ответы от разных пачек могут прийти не в порядке ID.

Протокол — строки с символом `\n` в конце:

```text
GET 1
1 1
GET 2
2 2
```

Первое число в ответе — ID запроса, второе — новое значение счётчика сервера. На некорректный запрос сервер отвечает `ERR invalid request` и не увеличивает счётчик.
